# Group call UI contract

Import the hooks from `useGroupCall.ts`. CallProvider owns the session and remote audio across routes and while minimized. The UI owns surfaces, routing, focus, layout, copy, and video elements. An explicit Start or Join is required after reload, lock, or a native incoming notification tap.

## Entry points

| Surface | Hook | State and action |
| --- | --- | --- |
| Group TopBar | `useGroupCallBanner(conversation)` | `hidden` for pending members or when rollout is off and there is no room. `start` opens the picker. `needs_members`, `timed_out`, and `unsupported` provide disabled or hidden actions per the design. |
| Ring members picker | `useRingMembersPicker(conversation, type)` | `members`, `canRing`, `loading`, `maxSelections`, and `defaultSelectedUserIds`. Default selects all eligible members when the accepted group fits. Larger groups begin with an empty selection. Confirm with `actions.start(conversationId, type, selectedIds)`. An empty selection starts quietly. |
| Global incoming | `useGroupCallInvitation()` | `invitation` is the selected live ring. Its `ringFrom` identifies the actual ringer, including re-rings. `room` supplies the roster and capacity. While `keyReady` is false use the existing secure-invitation preparation state. Call `joinInvitation(invitation, cameraOff?)` or `decline(invitation)`. The sheet closes when ringing expires, the room fills, or any device joins or declines. The banner remains available. Generic ring pushes open a group only when one eligible group can be resolved after unlock. |
| Busy toast or quiet notice | `useGroupCallInvitation()` | `notice` is a `ring` suppressed by an ongoing call or a `quiet` announcement. Use `conversationId` for Open chat and call `clearNotice()` after handling it. The notice never grants media consent. |
| Chat banner | `useGroupCallBanner(conversation)` | `waiting` or `active` → Join. `join_here` → the signed-in user is on another device and can move their seat. `return` → restore. `full`, `timed_out`, and `unsupported` → disable or omit Join. `room`, `maxParticipants`, `elapsedSeconds`, and `timedOutUntil` provide the labels. |
| Chat list | `useGroupCallActivityIndicator(conversationId)` | Returns an active call ID or `null`. One provider-level lookup refreshes the list. |
| Timeline | `useGroupCallBanner(conversation).timeline` | Up to 40 completed `GroupCallTimelineEvent` entries and the live call, newest first. Use `startedAt`, `endedAt`, `initiatorId`, and `type` for start/end lines. `missed` is specific to this account and to an unanswered ring. |

`CallType` is `"audio" | "video"`. Capacity includes self and is fixed by the room type, 12 for audio and 8 for video, including camera-off joins. If two members start concurrently the second action joins the existing room. The picker exposes `available | in_call | ringing | declined | no_answer | left | needs_update | timed_out` with the member's role, name/avatar when available, and timing data. Ring cooldown is per user.

## Session and tiles

`useGroupCall()` exposes `session`, `room`, `participants`, `canEndForEveryone`, `maxParticipants`, `busy`, `error`, `ended`, `event`, and `actions`. The room has `id`, `conversationId`, `type`, `initiatorId`, `startedAt`, `aloneUntil`, and the authoritative attendees. `session` is null when this tab has no live local media session. Admins and the accepted starter may end for everyone.

| Field | Use |
| --- | --- |
| `session.stage` | `waiting` for the solo room, `connecting` while peers establish links, `live` when any tile connects, `reconnecting` during local signaling loss or when all available peers are reconnecting. |
| `participants[]` | Remote tiles keyed by user ID. The session ID changes on handoff. The DO roster still counts a user if this client loses that peer's individual media link. |
| `tile.stage`, `tile.keyWaiting` | `connecting`, `live`, or `reconnecting`. `keyWaiting` selects the secure-media reconnect text. A peer that exceeds its local recovery deadline goes out of the tile list and emits `lost_connection`. |
| `tile.stream`, `tile.screen` | Remote camera/audio and separate screen-share streams stay stable for the life of a peer connection. A signaling outage withdraws those streams until the server confirms the current roster and the peer connections are rebuilt. Sender transforms also stop on an expired roster heartbeat, including if the socket goes silent without closing. Tracks are published only after an authenticated frame. Attach video elements muted and use the existing playback recovery context. Group audio elements already live in CallProvider. |
| `tile.media`, `tile.videoPaused` | Authenticated remote `muted`, `cameraOff`, `sharing`, and `receivingVideo` are null before an authenticated media-state event. `videoPaused` also reflects local inbound video suppression. |
| `tile.quality`, `tile.speaking` | `ok | poor` after sustained loss/RTT, and an audio-level speaking indicator. |
| `session.localStream`, `session.localScreen`, `session.media` | Self preview, separate local screen share, and capture state. `mediaError` is `microphone | camera | screen | null`. A denied capture leaves the participant in the room as a listener. |
| `session.secureMedia` | At least one peer has delivered a successfully authenticated frame. |
| `session.activeSpeakerId`, `spotlightUserId` | Spotlight follows pinned user, screen sharer, active speaker, then the first remote tile. The UI chooses the responsive grid/spotlight layout when preference is `auto`. |
| `event` | Latest `joined | sharing | left | lost_connection | removed | timed_out` with user ID and time. Expires after four seconds. |
| `ended` | Snapshot and `GroupCallExitReason` for the end surface. `room.endedBy` identifies a moderator or starter who ended it. `dismissEnd()` clears the local screen state. |

`join(conversationId, callId)` and `joinCameraOff(conversationId, callId)` are explicit banner/late-join actions. `leave()` clears local media immediately. `endForEveryone()` is ready for the UI confirmation. `ring(userIds)` accepts IDs from the participant picker. `toggleMute()`, `toggleCamera()`, `retryMicrophone()`, `selectCamera(id)`, and `toggleScreenShare()` control the local media. Screen sharing and cameras apply to video rooms. Use `session.canShareScreen` and `session.screenShareOwnerId` to disable sharing while another participant is presenting. `pin(userId | null)`, `setLayout("auto" | "grid" | "spotlight")`, `setSelfViewHidden(boolean)`, `minimize()`, and `restore()` change this tab's presentation preferences.

Actions that call the service resolve `{ ok: true } | { ok: false, code: GroupCallErrorCode }`. Use `groupCallErrorTranslation` and `groupCallExitTranslation` from `group-call-messages.ts` for localized logic states. Transfer and removal reasons are `moved` and `removed`. A timeout blocks admission and also ejects a member timed out mid-call. Other reasons are `timed_out`, `left`, `lost_connection`, `empty`, `alone`, `ended_for_everyone`, and `group_deleted`.

## Rollout, storage, and verification

- `GROUP_CALLS_ENABLED=true` enables new group rooms. The default is off. Existing rooms can finish, reconnect, and accept late joins after disabling new starts. A client advertises `group-call-v1` only when it supports encoded transforms. Ring presence and push delivery are capability-specific. Direct calls retain their legacy v1 protocol and endpoints. Group sockets use routed v2 with replay per destination user/device/session. Group call control sends, pre-key lookups, and sync use a separate authenticated rate budget.
- Rehearse `0022_group_calls.sql` against a pre-0022 copy after 0021. Apply it once before loading the new Worker. It adds default-zero device and push-subscription capabilities and an active-room lookup. Apply `0023_group_call_quiet_push.sql` next for the independent quiet-notice cooldown. The current base schema includes both migrations. For rollback, stop new rooms and let active rooms drain first, then leave the additive schema in place. The previous Worker uses the original direct-call table and protocol. If a rollback skips draining, the group client loses signaling and the updated Worker must clear expired lookups when it resumes. The group DO owns roster, leases, replay, and bounded timeline.
- Ring proofs and frame keys share a device-addressed Double Ratchet control channel with independent outbound and inbound session state. Chat keeps its original ratchet. Key delivery and sender enablement are per peer. The receive pipeline commits the authenticated receipt and KEK-wrapped payload in the same transaction. Join, leave, handoff and moderation change the roster epoch. Old keys and stale destination buffers cannot authorize media for a new epoch. Reports to `POST /api/group-calls/metrics?cap=group-call-v1` are authenticated, rate-limited and allow only an event kind, participant bucket, media type and platform.
- Device verification needs Chromium and Safari/WebKit encoded transforms, TURN and restrictive-network ICE restart, three or more simultaneous devices with late join and handoff, 8-video/12-voice boundary behavior, screen-share track ordering and playback recovery. On the Android shell verify service audio continuity, camera release/resume, incoming notification consent, ongoing notification actions, and lock cleanup. Verify old 0.1.0 apps still make direct calls and never ring for groups. Use local or isolated preview resources.
